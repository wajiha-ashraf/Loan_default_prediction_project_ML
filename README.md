# Loan Default Prediction

A machine learning project that predicts whether a borrower will **default on a loan**, using only information available at the time the loan application is made (LendingClub historical data, 27,003 loans).

## Why this project is different from a typical "tutorial" version

Most public notebooks on this dataset report 95–99% accuracy. That number is **fake** — it comes from leaving in columns like `total_pymnt`, `recoveries`, and `last_pymnt_amnt`, which only exist *after* the loan has already started being repaid (or has defaulted). A model trained on those columns has essentially seen the answer already; it would be useless for actually deciding whether to approve a new loan.

This project explicitly drops every post-origination column and trains only on data that would genuinely be available at underwriting time. The result is a lower but **honest and realistic** score (~0.71 ROC-AUC), which is in line with published benchmarks for unsecured consumer credit risk models built on application-time features only.

## Results

| Model | ROC-AUC | F1 (tuned threshold) | Accuracy (tuned threshold) |
|---|---|---|---|
| **Logistic Regression** (best) | **0.709** | 0.373 | 0.713 |
| XGBoost | 0.706 | 0.363 | 0.719 |
| Random Forest | 0.704 | 0.360 | 0.709 |

- Class imbalance (only ~14.7% of loans default) is handled with class weighting, and the decision threshold is tuned on the precision-recall curve rather than using the default 0.5 cutoff — raw accuracy is a misleading metric on imbalanced data.
- Evaluation uses a held-out 20% test set with stratified sampling.

## How to run
```bash
pip install -r requirements.txt
jupyter notebook loan_default_prediction.ipynb
```
Run all cells top to bottom. It will reproduce the EDA plots, train all three models, save the best one to `models/loan_default_model.pkl`, and show an example of scoring a new applicant.

## Pipeline overview
1. **Load & explore data** — check target imbalance.
2. **Drop leakage columns** — anything only known after the loan is funded.
3. **Feature engineering** — parse `%`/text fields into numbers, derive credit history length, convert sparse "months since X" columns into simple flags.
4. **Preprocessing pipeline** — median/most-frequent imputation + scaling/one-hot encoding, wrapped in a `ColumnTransformer` so there's no leakage between train/test.
5. **Train 3 models** — Logistic Regression, Random Forest, XGBoost, all imbalance-aware.
6. **Evaluate** — ROC-AUC, precision, recall, F1, confusion matrix; pick best model by ROC-AUC and tune its decision threshold.
7. **Feature importance** — see which application-time factors matter most.
8. **Save & demo** — persist the full pipeline and show it scoring a new application.

## Notes for resume / interview talking points
- Correctly identified and removed **data leakage**, a very common real-world ML mistake — good talking point to show data-science maturity, not just "got high accuracy."
- Handled **class imbalance** properly (class weighting + threshold tuning instead of naive accuracy optimization).
- Delivered a **single deployable artifact** (full sklearn pipeline, not just a bare model) so raw new applications can be scored directly.

## Possible extensions
- Try SMOTE / other resampling techniques and compare to class-weighting.
- Hyperparameter tuning via `GridSearchCV`/`Optuna`.
- Probability calibration (`CalibratedClassifierCV`).
- Cost-sensitive threshold selection (cost of a missed default vs. cost of rejecting a good loan) instead of pure F1 optimization.
- Deploy as a simple API (FastAPI/Flask) around `models/loan_default_model.pkl`.
